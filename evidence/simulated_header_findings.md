# Simulated Email Header Investigation

## Case Information

Case ID: PHISH-2026-001

Evidence File: samples/simulated_email_headers.txt

Evidence Type: Fictional Training Data

Investigation Status: Practice Analysis

## 1. Sender Identity

Observed From:
[security@example.net](mailto:security@example.net)

Observed Reply-To:
[account-help@example.org](mailto:account-help@example.org)

Observed Return-Path:
[bounce@example.org](mailto:bounce@example.org)

Finding:
The addresses differ. This is worth examining, but different addresses do not independently prove malicious activity.

## 2. Email Routing

Observed Received Entry:
mail.training.example (192.0.2.25) to mx.training.example

Finding:
This is a simulated routing entry. It cannot establish the actual origin or delivery path of a real email.

## 3. Authentication Results

Simulated SPF Result:
FAIL

Simulated DKIM Result:
NONE

Simulated DMARC Result:
FAIL

Finding:
These results are fictional and were not generated by real authentication checks. They are included only to practise interpreting header fields.

## 4. Risk Indicators

* Display name claims to represent a recognizable technology company.
* Reply-To and Return-Path differ from the displayed sender address.
* Simulated authentication results show SPF and DMARC failures.
* The email uses urgency and requests account verification.

## 5. Analyst Assessment

The simulated message contains several characteristics that would warrant further investigation in a real case.

However, no actual phishing activity has been established. The header values and authentication results are fictional.

## 6. Recommended Next Steps for a Real Case

1. Obtain the original email with complete headers.
2. Establish which mail servers added the Received entries.
3. Review SPF, DKIM, and DMARC results from a trusted receiving system.
4. Examine the sender and Reply-To domains.
5. Assess links and attachments using approved, safe analysis methods.
6. Preserve the original evidence and document the investigation.

## 7. Conclusion

This exercise demonstrates how email header fields can help structure a phishing investigation.

The findings are educational only and must not be represented as analysis of a real malicious email.
